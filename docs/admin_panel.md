# Адмінка

Потрібно все-таки зробити адмінку щоб розуміти що відбувається, хай її фронтенд живе на Cloudflare Workers (як і клієнт), а дані бере з api на публічному сервері, 
може бути на реакті з якимось легким ui-кітом і графіками на amcharts5, туди мають іти:

## Група "управління"

### Дашборд здоров'я - за замовчанням
історія старіша за тиждень затирається
- здоров'я мікросервісів на обох серверах + історія за тиждень з гранулярністю півгодини, закешована
- доступність фронтендів + історія за тиждень з гранулярністю півгодини, закешована
- перевірка функціонування всіх програмних компонентів + історія за тиждень з гранулярністю півгодини, закешована
    - по всіх пунктах - успіх або помилка з тултіпом деталей
    - відео пишеться, 
    - немає застарілих необроблених файлів, 
    - вебхук ПРРО регулярно працює
- телеметрія кожної POS з адресою, 
    - інфо чи працює raspberry, 
    - монітор - перевірка через raspberry чи працює,
    - інтернет-з'єднання
    - камера 
    - інтернет пінг, джиттер тощо (можливо легкий спідтест, з мінімальним навантаженням)
    - телеметрія з джетіно окремо сюди ж
    - распберрі колекціонує телеметрію локально та намагається надіслати (ідемпотентно), 
  так що якщо інтернет тимчасово не працюватиме, телеметрія прийде заднім числом

### Дашборд статистики
Фільтр по датах, за замовчанням останні 30 днів, можна обрати хоч весь період,
з розрізом у добу. Зібрано 23.09.2026 — одинадцять карток у тому ж порядку,
що в макеті, по три в ряд:

| Картка | Що показує |
|---|---|
| Дохід | гривні за добу, окремий ряд на точку |
| Покупки | ті самі чеки, кількістю |
| Події з камер | поки порожньо: камер немає, і графік каже це словами |
| Дохід за годиною дня | середнє за добу, колонками: у сумі не порівняти два різні проміжки |
| Дохід за днями тижня | те саме, але дільник свій на кожен стовпчик: понеділків у місяці 4 або 5 |
| Взаємодія з бонусами | бублик «забрали / лежить» за чеками періоду |
| Нарахування монет | срібні й золоті, за добу |
| Витрати монет | срібні й золоті, за добу |
| Кавові зерна | отримано й витрачено, чистими лініями |
| Редім бонусів | забрали проти незабраних |
| P2P оборот | кавенятка проти одягу, у жовтих монетах |

Третьої частки з макета — «ігнорують бонуси» — немає: чек без бонусу не
відрізнити від чека, за яким по бонус не прийшли. «Прострочених» бонусів
теж більше не буває — токен не згоряє (`db-schema.md`).

Рахунок закешований: типовий проміжок лежить у Redis до 04:00, свій проміжок
із фільтра рахується наживо. У ключі кеша є версія — інакше зміна складу
відповіді чекала б ранку.

### Дашборд квізів
Показує гістограмами або круговими діарграмами залежно від даних. Фільтр по даті, за замовчанням 30 днів останніх
- по анкетах профілю
- по напоях (з фільтром по напою - бонусні копії напоїв рахуються разом з основними)

## Група "операційка"

### Ціни
- Поточні ціни на всі напої - за замовчанням створює queued деплоймент цін на всі точки одразу (можна обрати конкретні), зі статусом окремо по кожній точці й по Checkbox
- контент акції береться з розділу **«Акції»** (23.09.2026): бібліотека
  панелей із полями, які вміє намалювати кіоск — плашка (Акція /
  Оголошення / Новина / без плашки), два рядки заголовка, акцентний рядок,
  дрібний рядок і напій, зі спрайта якого береться картинка. На «Цінах»
  акцію обирають зі списку, і деплоймент везе її на точку, 
- історія деплойментів цін (можуть бути queued, deploying, current, failed, history)

### Помилки (показує к-ть "непрочитаних")
Запити в форму "щось не працює"

### Підтримка (показує к-ть "непрочитаних")
Запити в телеграм-бот підтримки — наш бот на вебхуках (services.md, «Підтримка через Telegram»; зроблено 22.09.2026): повідомлення з Telegram лягають у support_threads/support_messages, оператор відповідає прямо звідси, лічильник на огляді — треди без відповіді. Треди, що прийшли з кнопки в застосунку, показують нікнейм гравця, решта — @username з Telegram; фото й файли тягнуться з Telegram, коли тред відкрили.

### Квізи (показує к-ть "непрочитаних")
Субміти квізів

### Замовлення 
Історія реальних замовлень для відправки новою поштою, з деталями замовлення та доставки, доказом з камери
- зміна статусу (друкуємо → пакуємо → відправлено → …; принт замовляється у Wolf, backend/api/data/shop-products.json) і створення ТТН прямо звідси; далі статус оновлює трекінг НП, і кожну зміну гравець бачить на екрані "Мої замовлення" (gamification_ui.md)

## Група "користувачі"

### Користувачі
Список користувачів з 
- балансами срібних і жовтих монет та бобів, 
- історією транзакцій в справжній та ігровій валюті, 
- інвентарем, 
- коли останній раз заходили
- історія чату за кавенятком
- історія відкриття лут боксів

### Покупки
Повна історія покупок з чекбокса, з бонусами та перевіркою чи їх редімнули (ссилка на юзера якщо так)
