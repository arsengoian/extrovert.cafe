# ПРРО Checkbox — вебхук

Джерело подій про реальні продажі. Потрібне для двох речей:
нарахування бонусів у гейміфікації і **доведення обороту орендодавцю**
під схему «фікс + % від продажів».

## Перевірити ПЕРЕД тим, як щось налаштовувати

1. **Чи в нас узагалі Checkbox.** Фіскалізацію ставить Zernova через
   Ingenico Self 2000 з рахунком Приватбанку. Ingenico — це платіжний термінал,
   а ПРРО-софт зверху може бути будь-який. Якщо не Checkbox — усе нижче не діє.
2. **Чи вебхук уже зайнятий.** Налаштування зберігаються окремо для кожної каси,
   і URL там **один**. Якщо Zernova або інтегратор термінала вже щось повісили,
   наш `POST` мовчки перезапише їхнє. Спершу `GET`.

## API

Базовий URL `https://api.checkbox.in.ua`, специфікація `checkbox API 2.104.1`.

```
POST   /api/v1/webhook   {"url": "https://..."}   → повертає key
GET    /api/v1/webhook                            → url, created_at, updated_at,
                                                     last_error_date, last_error_message
DELETE /api/v1/webhook
```

`key` — секрет для підпису. `last_error_*` показує, коли наш приймач не відповідав:
дірки в даних будуть видимі, а не мовчазні. Варто перевіряти по крону.

## Підпис

```
base64(HmacSHA256(key, тіло_запиту_як_UTF8_байти))
```

Перевіряти **обовʼязково**. Без цього будь-хто зможе слати нам фальшиві продажі
і накручувати бонуси.

## Що прилітає

Події фіскалізації чека, відкриття й закриття зміни, службові внесення й видачі.
Ключові поля чека: `id`, `fiscal_code`, `fiscal_date`, `total_sum`, `goods`,
`payments`, `shift`, **`tax_url`** — посилання на сторінку ДПС.

`tax_url` — саме те, що робить звіт орендодавцю таким, що перевіряється третьою
стороною, а не «ось мій ексель».

## Наш приймач

Мікросервіс `checkbox/`:

1. `POST /webhook/checkbox` — перевірка HMAC, ідемпотентність за `id` чека
2. запис у Postgres (сирий payload + розібрані поля)
3. публікація події в Redis → `ws` штовхає її на кіоск і в телефон
4. **окремо: звірка.** Вебхук може не дійти. Раз на годину тягнути
   `GET /api/v1/receipts` за період і добирати пропущене — інакше загубимо продаж
   і не помітимо.
