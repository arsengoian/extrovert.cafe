# Схема URL

Точок буде більше однієї. Ідентифікатор точки закладено **зараз**, поки
переробляти дешево: змінити URL живого кіоска потім означає їхати на точку.

## Формат ідентифікатора

`^[a-z0-9][a-z0-9-]{1,30}$` — малі латинські, цифри, дефіс. Без крапок і слешів,
щоб не ламати роутинг і ключі R2. Перша точка — `kyiv-01`.

## Кіоск (pos)

| URL | Що |
|---|---|
| `/` | 302 на точку за замовчанням (`DEFAULT_POINT`) |
| `/p/<point>` | сторінка кіоска |
| `/api/v1/points/<point>/menu` | меню точки |
| `/api/prices` | **застаріле**, 308 на новий роут. Прибрати, коли Pi перепрошиємо |
| `/healthz` | пінг |

Сторінка визначає точку з `location.pathname`, а не зі змінної збірки —
один білд обслуговує всі точки. `localStorage` теж розділений по точках
(`extrovert.menu.<point>`), інакше друга точка показала б чужі ціни з кешу.

## Сховище меню

R2, ключ `points/<point>/menu.json`. Заливка:

```bash
node scripts/push-prices.mjs                  # kyiv-01, data/prices.json
node scripts/push-prices.mjs kyiv-02          # інша точка
node scripts/push-prices.mjs kyiv-02 ./m.json # інша точка й інший файл
```

Поки нової точки немає, воркер відкочується на старий ключ `prices.json`
і позначає це заголовком `x-legacy-key: 1`.

## Бекенд (api)

```
/api/v1/points/<point>/menu
/api/v1/points/<point>/events        стрічка подій точки
/api/v1/me                           профіль гравця
/api/v1/me/plants                    кавенятка
```

## Події (ws)

`wss://ws.extrovert.cafe/v1/points/<point>` — кіоск слухає свою точку.
`wss://ws.extrovert.cafe/v1/me` — телефон слухає свій акаунт.
