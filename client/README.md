# client — застосунок гравця

Те, що користувач відкриває, відсканувавши QR на стійці або на стаканчику.
Гейміфікація: вирощування кавенятка, монетки, бонуси, інфоматеріали.

Екрани й механіки — `../docs/gamification_ui.md`, економіка —
`../docs/gamification_economy.md`, графіка кавенятка —
`../docs/bush_graphics_customization.md`.

**Стек: React + Vite**, статика на Cloudflare Workers, дані з `api`, події з
`ws`. Один фреймворк із адмінкою — обґрунтування в `../docs/roadmap.md` §1.
Коду тут поки немає, лише заготовка.

## Що врахувати з самого початку

- **Перехід із кіоска — QR із claim-токеном** (`bonus_grants.claim_token`,
  вікно 2 хв): скан забирає бонус на пристрій, редім — уже після авторизації.
  Останній POS і незаредімлені бонуси живуть у localStorage.
- **Офлайн.** Люди стоять біля автомата в підвалі ТРЦ. Стан кавенятка має
  переживати втрату мережі.
- **Кавенятко малюється поза React.** Десятки спрайтів і анімацій — це
  канвас або CSS зі своїм циклом; React тримає стан UI, а не кадри. Інакше
  перформанс на телефоні впирається в перемальовки дерева.
- **Без реєстрації на першому екрані.** Бонус можна забрати й без акаунта,
  акаунт потрібен лише щоб його зарахувати — інакше відвалиться більшість.
